# Splice

Splice — язык для CPU-ядер, которые специализируются по данным приложения после его запуска. Функция с атрибутом `#[kernel]` сохраняет обычный вызов Rust. Макрос также создаёт фабрику JIT-кода. Тип в `build::<B>()` определяет, какой компилятор обработает ядро.

```rust
use splice::{Executable, kernel};
use splice_cranelift::Cranelift;
use splice_lancy::Lancy;
use splice_llvm::Llvm;
use splice_text::Text;

enum Price { Retail, Wholesale(i32) }

#[kernel]
fn total(#[comptime] plan: &Price, price: i32, qty: i32) -> i32 {
    match plan {
        Price::Retail => price.wrapping_mul(qty),
        Price::Wholesale(discount) => price.wrapping_sub(*discount).wrapping_mul(qty),
    }
}

fn main() -> Result<(), String> {
    let plan = Price::Wholesale(3);
    let fast_build = total::build::<Lancy>(&plan)?;
    let cranelift = total::build::<Cranelift>(&plan)?;
    let llvm = total::build::<Llvm>(&plan)?;
    let listing: String = total::build::<Text>(&plan)?;
    print!("{listing}");
    assert_eq!(fast_build.call(&[10, 4], &mut [])?, 28);
    assert_eq!(cranelift.call(&[10, 4], &mut [])?, 28);
    assert_eq!(llvm.call(&[10, 4], &mut [])?, 28);
    Ok(())
}
```

Вызов `build::<Lancy>` строит SSA HIR Lancy прямо при обходе кернела. Вызов `build::<Llvm>` таким же образом строит LLVM IR. Вызов `build::<Cranelift>` строит и проверяет переносимый IR, затем компилирует его в машинный код через Cranelift. Хостовый Rust выбирает вариант `match` по плану, вычисляет известные выражения и разворачивает `for` по `#[comptime]`-срезу. Параметры специализации могут содержать заимствования и пользовательские enum. Объявление `let mut slots = vec![initial; count]` создаёт в ядре отдельный регистр для каждого элемента. Размер коллекции и индекс `slots[i]` должны быть известны при специализации.

В пределах одной сборки вложенные вызовы делят тело по объявлению функции, её параметрам типа и значениям `const`- и `#[comptime]`-аргументов. Обычная функция без параметров специализации строится один раз. Для чисел, строк и срезов ключ учитывает содержимое. Для своих структур и перечислений можно добавить `#[derive(splice::ComptimeKey)]`, а для параметра типа — ограничение `T: splice::ComptimeKey`. Аргументы с состоянием, для которых ключ не задан, сохраняют отдельный обход тела при каждом вызове.

`build::<Text>` возвращает текст функции после специализации. В примере сигнатура содержит только `price` и `qty`, а скидка 3 появляется в теле перед умножением. В листинге сохраняются имена параметров, операции со срезами и вызовы. Повторные вызовы одной специализации ссылаются на одно определение. Переходы между метками показывают оставшиеся runtime-ветвления и циклы. Листинг отражает семантику Splice до оптимизаций машинного бэкенда.

Сигнатура фабрики — `build::<T>(...) -> splice::Result<T::Output>`. У `Text` тип результата успешной сборки — `String`, у Lancy, Cranelift и LLVM — исполняемый кернел. Ошибки специализации и кодогенерации возвращаются через `Err(String)`. Для сравнения бэкендов на одном переносимом IR можно вызвать `let ir = total::ir(&plan)?;`, а затем `Lancy::compile(&ir)?`, `Cranelift::compile(&ir)?`, `Llvm::compile(&ir)?` или `Text::compile(&ir)?`, импортировав трейт `splice::Codegen`.

Скалярные аргументы `i32` и типизированные срезы передаются двумя списками с сохранением порядка внутри каждого списка. Все три компилятора поддерживают вызовы других ядер, циклы, ранний возврат, проверяемые обращения к срезам и целочисленное деление. Обработка колонок выражается обычным циклом над срезами.

## Векторный SQL-план

В `sql_plan` дерево из `Scan`, `Filter`, `Project` и `Join` специализируется при сборке. Таблица хранит ключи и значения в двух непрерывных колонках. Одна полоса `Lane<i32>` соответствует одной строке. `Scan` читает пачку соседних строк, `Filter` вычисляет маску предиката и уплотняет обе колонки по этой маске, а `Project` вычисляет обе выходные колонки из одной исходной пачки. При последовательном чтении короткий маскированный пролог выравнивает адрес первого потока, хвост также проходит под маской. Начало второй колонки может иметь другое выравнивание.

При специализации каждый правый вход `Join` получает свой индекс с открытой адресацией и линейным пробированием. Строки с одинаковым ключом связаны в список значений. Левый вход проходит от скана через предикаты, проекции и соединения в виде SIMD-пачек. `gather` читает слоты полной пачки. Совпадения переходят к чтению значений, продолжающие поиск полосы уплотняются через `compress`, а `expand` заполняет свободные позиции новыми запросами. Чтение значений использует такую же дозагрузку, в том числе при обходе дубликатов. Когда вход исчерпан, оставшиеся полосы дочитываются скалярно. В рабочем буфере размещаются правые хеш-индексы и итоговые пары `(key, value)`. Порядок выдачи после соединения свободный. [Код операторов](splice/examples/relational/kernels.rs) · [Специализация дерева](splice/examples/relational/pipeline.rs) · [План по пяти таблицам](splice/examples/relational/pricing.rs)

```sh
cargo run -p splice --release --example sql_plan -- lancy
cargo run -p splice --release --example sql_plan -- cranelift
cargo run -p splice --release --example sql_plan -- llvm
cargo run -p splice --release --example sql_plan -- text
cargo bench -p splice --bench backends -- sql_plan
cargo test -p splice --release --example sql_plan --test simd
```

Стенд Criterion.rs измеряет проекцию по 65 536 строкам и SQL-план с четырьмя хеш-соединениями. В таблице продаж 29 360 128 строк, в каждом из четырёх справочников по 1 835 008 товаров. Один вызов SQL-плана возвращает 11 010 048 строк. Данные фиксированы для всех бэкендов и готовятся до измерения.

Для одного SQL-плана выполните `cargo bench -p splice --bench backends -- sql_plan`. Фильтр `sql_plan/execute/build` выбирает вызовы ядер, собранных через `build::<B>`. Каждый замер `compile/build` включает специализацию и установку нового исполняемого ядра. Для Cranelift этот путь включает построение переносимого IR. Группа `stage_ir` измеряет построение IR отдельно, а `compile/from_ir` передаёт всем трём бэкендам одну готовую функцию. Освобождение JIT-кода происходит после замера сборки. Группы `execute/build` и `execute/from_ir` повторно вызывают готовые ядра на одних входах с заранее выделенным выходным буфером. Для SQL-плана стенд до и после измерений проверяет значения и число вхождений каждой пары по отдельной скалярной формуле для исходных данных.

## SIMD в ядрах

`Lane<T>` представляет один вектор. Обычная Rust-функция и все три JIT используют одинаковую ширину на текущей машине. `Lane::<T>::lanes()` возвращает число **элементов**. Например, для 32 байт это восемь `f32` или четыре `f64`, для 64 байт — шестнадцать или восемь. В переносимом IR размер вектора определяется типом элемента при компиляции бэкендом.

```rust
use splice::{kernel, Executable};
use splice_lancy::Lancy;

#[kernel]
fn add_block(a: &[u16], b: &[u16], dst: &mut [u16]) -> i32 {
    use splice::simd::Lane;
    let x = Lane::load(a, 0);
    let y = Lane::load(b, 0);
    (x + y).store(dst, 0);
    Lane::<u16>::lanes() as i32
}

let n = splice::simd::Lane::<u16>::lanes();
let (a, b, mut dst) = (vec![u16::MAX; n], vec![1u16; n], vec![9u16; n]);
let jit = add_block::build::<Lancy>()?;
let count = jit.call(&[], &mut [a.as_slice().into(), b.as_slice().into(), dst.as_mut_slice().into()])?;
assert_eq!(count as usize, n);
assert_eq!(dst, vec![0u16; n]);
```

- Элементы векторов и срезов поддерживают `u16`, `i32`, `i64`, `f32` и `f64`. `+`, `-` и `*` для целых выполняются по модулю разрядности. Целые поддерживают побитовые операции, вещественные — деление. `splat` заполняет полосы одним значением, включая runtime-параметр `i32`. `iota()` нумерует их с нуля.
- Поэлементные сравнения `simd_eq/ne/lt/le/gt/ge` дают `Mask<T>`. Маску, полученную сравнением целочисленных индексов, можно применять к вещественным данным той же разрядности. Маски поддерживают `&`, `|`, `^`, `!`, `any()`, `all()` и `select(yes, no)`. Для `a.add_masked(mask, b, fallback)` каждая выключенная полоса берётся из соответствующей позиции `fallback`.
- Маска `Lane::<T>::first_n(remaining)` включает первые `min(remaining, Lane::<T>::lanes())` полос. Для хвоста используйте `Lane::load_select(src, offset, mask, fallback)` и `value.store_select(dst, offset, mask)`. Смещения и индексы измеряются в элементах. `Lane::gather(src, indices)` и `value.scatter(dst, indices)` принимают столько индексов, сколько полос в данных. Для `u16` это `Lane<u16>`, для `i32/f32` — `Lane<i32>`, для `i64/f64` — `Lane<i64>`. Маскированные формы — `Lane::gather_select(src, mask, indices, fallback)` и `value.scatter_select(dst, mask, indices)`.
- Выключенная полоса не обращается к памяти. Записи идут по возрастанию номера полосы. При повторении индекса остаётся последняя выполненная запись. Первый активный индекс за границей завершает Rust-вызов паникой, JIT-вызов возвращает ошибку. Оба сохраняют все записи до этой полосы, в том числе при неполном последовательном `store`.

Для `Lane<i32>` доступны `compress(mask)` с нулевым хвостом и `compress_store(dst, offset, mask)` с записью ровно `mask.count()` элементов в порядке исходных полос. `prefix_sum()` вычисляет включительную префиксную сумму с переполнением по модулю 2³². `expand(mask, fallback)` заполняет выбранные позиции последовательными элементами из начала вектора. Остальные позиции сохраняют значения из `fallback`. `extract_wrapping` и `replace_wrapping` читают и заменяют полосу по индексу, взятому по модулю числа полос. `last()` извлекает последнюю полосу, `swizzle(indices)` возвращает ноль для индексов за пределами вектора. `interleave_low/high` и `deinterleave_even/odd` переводят пары колонок в чередующийся формат и обратно. `>>` с известным при специализации числом бит выполняет арифметический сдвиг вправо. `Lane::<i32>::alignment_prefix(slice, offset)` возвращает число элементов до ближайшего выровненного адреса, включая ноль для уже выровненного входа.

Вспомогательный `#[kernel]` может принимать и возвращать `Lane<T>` или `Mask<T>`. При специализации такой вызов встраивается в вызывающее ядро. Для локального результата другого векторного ядра укажите тип, например `let keep: Mask<i32> = matches_rows(pred, keys, values);`.

### Два SIMD-ядра в работе

[`simd_matmul`](splice/examples/workloads/matmul.rs) перемножает две прямоугольные матрицы `i32` в построчном формате. Одна полоса накапливает один столбец результата. Ядро размножает `A[row, k]` через `splat` и читает соседние элементы строки B одним вектором. Блок из 16 строк A переиспользует панель B глубиной до 32 элементов и шириной до четырёх векторов. Остаток строки обрабатывается под маской. Арифметика выполняется по модулю 2³².

[`simd_hash_lookup`](splice/examples/workloads/probe.rs) ищет пачку ключей в таблице с линейным пробированием. Каждая полоса вычисляет начальный слот своего ключа. `gather_select` читает очередной слот для активных полос, найденные позиции сохраняются, а совпадение или пустая ячейка выключает полосу. После полного обхода поиск завершается и в заполненной таблице. Ёмкость таблицы — степень двойки, ноль обозначает пустую ячейку. Результат запроса — номер слота или `-1`.

```sh
cargo run -p splice --release --example simd_matmul
cargo run -p splice --release --example simd_hash_lookup
cargo test -p splice --release --example simd_matmul --example simd_hash_lookup
cargo bench -p splice --bench backends -- simd_
```

Наборы данных детерминированы. Перед измерением и после него стенд сверяет весь выход с независимой скалярной реализацией. Группы `compile` и `execute` измеряют сборку и повторный вызов отдельно для каждого из двух путей — `build` и `from_ir`.

## Сборка

Нужен Rust 1.94+. На Windows и Linux x86-64 доступны Lancy, Cranelift и LLVM. На Linux AArch64 доступны Cranelift и LLVM. Собственный генератор Lancy рассчитан на x86-64. Бэкенды Lancy и Cranelift собираются отдельно от LLVM. Для приложения с Cranelift достаточно зависимостей `splice` и `splice-cranelift`.

* **Windows x64 MSVC.** Для `splice-llvm` выбран LLVM 19.1. Сборка находит LLVM в стандартном каталоге или в компонентах C++ Clang для Visual Studio. Для другой папки установки задайте `LLVM_SYS_191_PREFIX` до сборки. В ней должны быть `lib/LLVM-C.lib` и `bin/LLVM-C.dll`. Cargo подготавливает DLL для `cargo run`, тестов и бенчмарков. Для самостоятельного запуска готового приложения положите соответствующую DLL рядом с исполняемым файлом или добавьте её каталог в `PATH`.
* **Linux x86-64 и AArch64.** Выбран LLVM 21.1 с динамической линковкой. Нужны инструменты разработки, включая `llvm-config-21`, и разделяемая библиотека LLVM. Для отдельной установки укажите префикс через `LLVM_SYS_211_PREFIX`.

Версии Inkwell и LLVM указаны в [манифесте бэкенда](splice-llvm/Cargo.toml). Операции над LLVM-инструкциями, типами, значениями и базовыми блоками используют [Inkwell Builder](https://docs.rs/inkwell/0.11.0/inkwell/builder/struct.Builder.html).

### Выбор SIMD-профиля

Задайте `SPLICE_SIMD` до запуска процесса. `auto` выбирает профиль по возможностям CPU и ОС. Явный профиль позволяет проверить более раннюю ISA на новом процессоре. Если CPU или ОС не поддерживают указанный профиль, JIT возвращает ошибку сборки. Обычная Rust-функция использует ту же ширину, что и JIT, и сообщает об ошибочном профиле паникой при запросе полос.

| Платформа | `SPLICE_SIMD` | Логическая ширина |
| --- | --- | --- |
| x86-64 | `sse`, `avx2`, `avx512` | 16, 32, 64 байта соответственно |
| x86-64 | `avx10` | По CPUID и состоянию XSAVE. Для LLVM нужны хотя бы 32 байта, LLVM использует набор AVX10.1. |
| Linux AArch64 | `neon` | 16 байт |
| Linux AArch64 | `sve`, `sve2` | 16, 32 или 64 байта, в пределах SVE VL потока при первом использовании SIMD |

На AArch64 `auto` предпочитает SVE2, затем SVE и NEON. LLVM выбирает инструкции SVE/SVE2 для фиксированных векторов, когда позволяет их ширина. Для 128-битных векторов LLVM может выбрать NEON. Если другой поток уменьшил SVE VL ниже ширины ядра, LLVM JIT возвращает ошибку до вызова машинного кода. Cranelift использует 128-битные части общего логического вектора и поддерживаемые им инструкции хоста. В профиле `sse` Cranelift может использовать доступные SSSE3 и SSE4.

В PowerShell задайте профиль перед вызовом Cargo, например `$env:SPLICE_SIMD = 'avx2'`.

```sh
# На x86-64 с AVX2
SPLICE_SIMD=avx2 cargo run -p splice-target --example simd_profile
SPLICE_SIMD=avx2 cargo test -p splice --release --test simd

# На Linux AArch64
SPLICE_SIMD=neon cargo test --workspace --exclude lancy --exclude splice-lancy --release

# На Linux AArch64 с SVE2
SPLICE_SIMD=sve2 cargo test -p splice-llvm --release
SPLICE_SIMD=sve2 cargo test -p splice --release --test simd

# На Linux AArch64 с QEMU user-mode
SPLICE_SIMD=sve2 \
CARGO_TARGET_AARCH64_UNKNOWN_LINUX_GNU_RUNNER='qemu-aarch64 -cpu max,sve-default-vector-length=64' \
cargo test -p splice-llvm --release --target aarch64-unknown-linux-gnu
```

GitHub Actions проверяет NEON на нативном ARM64-раннере и запускает SVE/SVE2 под QEMU с длинами 32, 48 и 64 байта. На x86-64 CI выполняет SSE и остальные профили, которые ОС видит на процессоре раннера. Тест SVE2 проверяет наличие `eor3` в листинге LLVM и сравнивает результат обоих путей компиляции с обычным поэлементным вычислением. [Workflow](.github/workflows/simd.yml)
