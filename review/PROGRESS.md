Тест `splice/tests/conversions.rs`: все допустимые `Cast/Widen/Narrow` × Lancy/Cranelift/Llvm/LlvmManualSimd × build/compile против Rust `as` (NaN, ±inf, −0, границы насыщения). Прогнан при `SPLICE_SIMD=auto|avx2|sse`. Это зачаток харнесса Ф1.5.

### Ф0.4 — HIR-01, HIR-13: scratch и отладочная область при инлайнинге (коммит 5af261a)
- По Р10(а): `Op::CallScratch { offset, bytes }` (смещение кратно 8), у Rust packet call — собственное смещение пакета в scratch (пакет пишется в ту же память, иначе инлайненный вызов затирал бы scratch вызывающей). Верификатор: `IrError::InvalidScratch`.
- Инлайнер сдвигает scratch/packet/`DebugStore` вызываемой функции выше собственных областей вызывающей (`Function::scratch_bytes/debug_bytes`); `check_expansion` ограничивает вложенные суммы `u32` (`FrameOverflow`). LIR x64/AArch64 адресуют `scratch_base + offset`.
- Интерпретатор получил scratch на кадр (только raw-режим), filetest-прогон без буфера идёт через `call_raw`. Синтаксис `.lancy`: `call_scratch OFF BYTES`, `debug_store OFF v`; листинг пакета — `... scratch N`.
- Тест `lancy/filetests/passes/inline-call-scratch.lancy` (Always/Never → 719, пакетный вызов, debug-область); падает при отключённом сдвиге. Прогнан на x64 и под qemu AArch64 (neon). `memory.rs` (must-alias по смещению) не трогал — корректность не требует, это оптимизация для Ф5.

### Ф0.5 — MAC-02 быстрый фикс
- `assignment()` применяет то же правило, что `binary()`: составное присваивание runtime-`usize` отвергается. Из-за MAC-01 ядро пока молча откатывается в Rust-импорт, поэтому результат совпадает с Rust; trybuild-сообщение появится, когда Ф7 (Р4) сделает откат ошибкой.
- **Ф4 обязана заменить** эту заглушку настоящим 64-битным `Index` (Р6) с беззнаковыми checked-операциями и убрать запрет из `assignment()`/`binary()`; тест `language.rs::compound_index_assignment_matches_rust_usize` при этом должен остаться зелёным уже на JIT-пути.
- Тест сравнивает Lancy/Cranelift/LLVM с Rust-функцией (паника ⇒ ошибка JIT) в debug и release; до фикса падал (`Ok(0)` против `Ok(1)` в release).

### Ф0.6 — MAC-03 (коммит 778b4e2)
- В `splice-core` один `HostFault` (деление на ноль / переполнение деления / переполнение) с i32-операцией ядра, которая ловит так же, и guard-трейты `HostArithmetic`/`HostShift`/`HostNegation` для всех целых примитивов (autoref: float и пользовательские типы — своими операторами). Макрос ставит guard перед host-бинарными, составными и унарным минусом; staged-код ловит в точке достижения, `comptime!` возвращает сообщение как ошибку сборки. `source::division_fault` → `source::fault_panic`.
- Тест `overflow.rs::host_arithmetic_faults_are_deferred_for_every_integer_type`: build без паники (хук паники на поток — эквивалент проверки `panic=abort`, отдельный бинарь не нужен), вызовы совпадают с Rust; Lancy/LLVM/Cranelift × build/compile × Release/Debug, cargo debug и release. До фикса падал.

### Ф0.7 — гигиена: MAC-04, MAC-05(б), MAC-22, MAC-23(часть) (коммит 673f35e)

### Ф0.8 — CORE-04 (коммиты 3704334, e90df0d)
- `immediate_condition` удалён из `KernelBuilder`, `FunctionBuilder`, splice-lancy и прямого LLVM-пути: бэкенды больше не помнят «последнюю константу». Сворачивание условий — во фронтенде: host-выбор макроса с ветками `Reg(Int|Bool)` даёт стадию `Word`, runtime-условие сворачивается через `RunArg::known`, поэтому все бэкенды и оба пути сборки видят одинаковый IR. Воспроизвести неверную компиляцию через публичный API не удалось; тест `language.rs::mixed_stage_conditions_fold_in_the_frontend_on_every_path` фиксирует семантику (известное условие — без `Branch`, неизвестное — с ним; прямой Text-build совпадает с `Text::compile`).
- Регрессия Ф0.6, найдена полным прогоном: отложенная ошибка host-`%` ловилась через `/`. `HostFault::Division*` теперь несут оператор (ловит тест `splice-text/tests/listing.rs`).

### Ф0.9 — BE-05 = CORE-15 (коммит 692d6ee)
- Отклонение от буквы Р11(а): «`extern` при подключённом LLVM» через Cargo-фичу невозможен, потому что фичи в воркспейсе унифицируются, и бинари lancy/cranelift без LLVM получили бы неразрешённые символы. Вместо этого на ELF символы `__jit_debug_*` определены как **weak** (`global_asm!`) и используются через `extern`. Статический LLVM даёт сильное определение (оно и используется, дубля нет), с `libLLVM.so` динамический линкер связывает LLVM с единственной экспортированной копией. Windows без изменений: LLVM там DLL со своими приватными копиями.
- `links = "splice_jit_gdb"` (+ пустой `build.rs`, его требует Cargo).
- Тест `splice-jit/tests/registry.rs` (регистрация попадает в общий дескриптор). Ручная проверка BE-05: тот же тест, слинкованный с `JITLoaderGDB.cpp.o` из `libLLVMOrcTargetProcess.a`, на старом коде падает (`rust-lld: duplicate symbol`), на новом проходит, `nm` показывает одно (сильное) определение. ### Ф1.1 — явный путь понижения (коммит e59f65a)
- Закрыто: MAC-01, MAC-08, SPL-04(а); Р4.
- `#[kernel]` = IR или `compile_error!` с исходной причиной и подсказкой; `#[kernel(rust)]` (на функции или методе `#[kernel] impl/trait`) — явный Rust-импорт. Эвристика `needs_rust_abi` (выбор Rust-ABI по синтаксису) удалена целиком вместе с `rust_region/LeafSyntax/calls_overload/supports_context_call`: маршрут — атрибут, а не догадка. `publish`/`trait_defaults` возвращают `syn::Result`, ошибки всех методов блока собираются вместе. Корень крейта — `#[kernel(crate = path)]` (позиционный путь никто не использовал, и он конфликтовал с `rust`).
- Rust-ядро публикует тот же API: `build_with_options`/`ir_with_options` (опции не влияют) и `print` (ошибка). Заимствованный `#[comptime]` у Rust-ядра — ошибка компиляции (раньше `Err` при `build`), ветки `borrowed_environment` удалены.
- Отклонение от плана: `Lowering`-константа и `TypedIr::lowering()` не добавлены. После Р4 маршрут детерминирован атрибутом, а у Rust-ядра `ir()` возвращает `RustImport`, не `TypedIr`; тест-сторож и `assert_lowered` стали бы тавтологией. «Каждое `#[kernel]` понижено» гарантирует макрос и проверяет trybuild.
- Найдено и исправлено: вызов локального значения-функции (`callback(x)` у `#[comptime] callback: fn(..)`) генерировал неверный Rust — теперь понятная ошибка (ui-тест). Заглушка `__SpliceOpaqueMethod` остаётся: она нужна для методов обычных (не `#[kernel]`) `impl`, которые макрос не видит; убрать можно только с моделью типов (Ф7).
- Тесты: 15 ядер с намеренным Rust-путём помечены `#[kernel(rust)]` (rust_regions + language); `trybuild` ui-тесты `splice/tests/ui/` (метка цикла, `i64`, MAC-02 составное присваивание `usize`, методы, требование трейта `Self::Output`, опции атрибута, заимствованный comptime). `compound_index_assignment_matches_rust_usize` проходил только через откат — заменён ui-кейсом; **Ф4 обязана вернуть его рантайм-версию** (см. git 16cb379) вместе с настоящим `Index`.
- CI arm64: `specialization_limits` падал под QEMU на 10-секундном watchdog (wall-clock). Watchdog удалён: завершение доказывают `is_err`-утверждения бюджета, зависание ловит `timeout-minutes` джобы (Ф1.6).
- Проверки: fmt, clippy `-D warnings`, `cargo test --workspace --release` — зелёные.

### Min/Max с плавающей точкой (коммит 6d1d681, по итогам CI)
- `hir::eval` задаёт Min/Max явно как IEEE 754-2019 minimumNumber/maximumNumber: NaN (в т.ч. sNaN) уступает числу, `min(-0, +0) = -0`, `max(-0, +0) = +0`. Ранее ответ зависел от цели: FMINNM на arm64 возвращал quiet NaN для sNaN, MINPS на x64 отдавал второй операнд при ±0.

### CI arm64: SVE с VL 48 байт (коммит 08b19f1)
- Строка QEMU `sve2 max 48 32` падала SIGSEGV в `sql_plan` только с LLVM. На main было LLVM 21, сейчас 19 (Р3); AArch64-бэкенд LLVM считает vscale степенью двойки, а VL 48 даёт vscale 3. ### Ф4.1 — регрессия `sql_plan/execute/build/lancy` после 6949f0f (коммит 7d5ac41)
- Причина (сравнение оптимизированного HIR Lancy и машинного кода ядра `query` до/после, временный дамп в `optimize_and_lower`): после оптимизации осталось 660 `bounds` против 276, код 49 222 байт против 41 244. ### Ф4.1b — ABI вызова ядра на словах `u64` (коммит 14a31d2)
- Закрыто: CORE-01 (ABI вызова ядра), временное ограничение `word_abi` удалено.
- `Executable::call(&self, args: &[u64], buffers) -> Result<u64, CallError>`: каждое скалярное слово — `Constant::bits` значения (младшие `ty.bits()` бит, выше нули; `bool` — 0/1, float — битовый образ IEEE). `KernelScalar` (`bool, i32, u32, i64, u64, usize, f32, f64`: `TYPE`, `to_word`, `from_word`) — кодирование для макроса, тестов и пользователей. `splice_core::validate_scalars(params, args)` — одна проверка числа слов и того, что в слове нет битов выше значения (`SignatureError::Word { index, ty }`); без неё бэкенды читали бы «грязное» слово по-разному (Lancy делает `0 - v` для `bool`, Cranelift/LLVM читают значение по ширине типа). Бэкенды хранят `params: Box<[ScalarType]>` вместо `arity`. Добавлены `impl Executable for &E` и `for Box<E>`.
- Cranelift: вход `(*const u64 слова, *const Descriptor, *mut u64 результат) -> i64 статус`; параметр загружается по своему типу со смещения `8·i` (хосты little-endian), результат входа всегда пишется в слово, обнулённое вызывающим (статус несёт только ловушку). LLVM: вход грузит `i64`-слова и сужает/`bitcast`-ит их по типу, результат расширяется нулями до `i64` (`from_word`/`to_word`). Lancy: `call_words` для чисто скалярной сигнатуры (вместо `call(&[i32])`), `call_raw` со срезами; узкий результат маскируется `Constant::new(result, word)`, потому что Lancy не обязан обнулять старшие биты.
- Макрос: `CallArgs::invoke` кодирует `KernelScalar::to_word`, результат — `<R as KernelScalar>::from_word`; `#[kernel]` принимает параметры и результат `usize` (раньше их отвергал `word_abi`, а сигнатура — сам макрос). Сообщения ui-тестов обновлены.
- Потребители: тесты, примеры и бенчмарки переведены; для ядер с одними `i32` — `splice_testkit::call_i32`. В бенчмарках и `relational::Catalog::run` результат декодируется `i32::from_word` до `usize::try_from` — иначе `-1` (ошибка ядра) стал бы большим `u64` и прошёл бы проверку.
- Тесты (testkit, 4 бэкенда × build/compile × Debug/Release): `every_scalar_type_passes_into_and_out_of_the_entry_at_its_position` (8 параметров всех типов, возврат k-го, без срезов и со срезом — оба пути вызова Lancy; падает при старом шаге `4·i` у Cranelift), `every_scalar_type_computes_on_entry_words_and_returns_one` (`Add`/`Xor` двух параметров каждого типа против `checked_eval`), `entry_words_must_hold_exactly_their_value`; `language.rs::usize_parameters_and_results_keep_all_64_bits` (значения 2^40, 2^63, `usize::MAX` через макрос). Тесты бэкендов теперь сравнивают слово результата с `Constant::bits` точно, а не `as i32`.
- Отклонение от плана: слова пакетов Rust-вызова, `ContextArguments` и скалярный импорт `(i32, i32) -> i64` остаются `i32`. Причина: Ф4.5 заменяет все три механизма Rust-вызова одним типизированным пакетом, а до Ф7.2 язык не может передать в импорт значение шире `i32`/`bool` (верификатор отвергает такие операнды при сборке, а не во время вызова). Расширение слов сейчас переписывало бы код, который 4.5 удаляет. Записано как вход для 4.5: «слово пакета — `u64` в кодировке `KernelScalar`, типы операндов из сигнатуры импорта».
- Проверки: clippy 1.94.1 `-D warnings` (`--all-features`, x86-64 и `--target aarch64-unknown-linux-gnu`), `cargo check --target x86_64-pc-windows-msvc --tests` (splice-core, splice-jit, splice-lancy, splice-cranelift), `cargo test --workspace --release --all-features` — зелёные. Прогретый вызов `projection/execute/build`: lancy 73.2 мкс (база 73.3), cranelift 128.4, llvm_manual_simd 32.5 — без замедления.

### Ф7.3 — ошибки компиляции вместо autoref (MAC-16)
- Стадирование (`__splice_inline`, `comptime!`, `print`) требует от типа известного значения свойств через границы трейтов с `#[diagnostic::on_unimplemented]`: чтение поля — `KernelType` (`evaluation::field`, ошибка указывает на поле), разыменование — только `&T`/`&mut T` (`evaluation::deref`, `BuiltinReference`), операторы и методы — `Primitive` (`evaluation::primitive`). Значение с drop glue, которое создаёт специализация (`evaluation::dropless`), и агрегат с деструктором в ядре, которое не может стать Rust-вызовом (`scalar::dropless_aggregate` вместо проверки в `scalar::aggregate`), — `const`-утверждения (ошибка мономорфизации, `cargo check` её не видит).
- Autoref остался только у необязательного вычислителя вызова с известными аргументами (`Lower::optional()` = `evaluator_return.is_some()`): там отказ — не ошибка, а откат к стадированию во время выполнения. Отложенные ошибки «field has no Splice layout description», «user-defined dereference», «user-defined operation in comptime!», «would run a destructor» из стадирования ушли.
- Найдено: пример `splice/examples/retry_policy.rs` падал при запуске (`Staging("field has no Splice layout description")`) — у `RetryPolicy` не было `KernelType`; теперь он не скомпилировался бы, derive добавлен, все примеры запущены вручную. То же у `Matcher` в `rust_regions.rs`. Примеры в CI не запускаются (только `simd_profile`) — оставлено как есть, ошибку теперь ловит компиляция.
- Тесты: ui `specialization_types.rs` (поле без layout, пользовательский `Deref`, пользовательский `Add` в стадировании и в `comptime!`), ui `comptime_drops.rs` (`const String`, `let` из `const` с `Drop`, агрегат с `Drop` в `usize`-ядре); до исправления все компилировались. Контрпримеры — `tests/ui-pass/specialization_types.rs`; из-за pass-кейса trybuild собирает (`cargo build`), а не только проверяет, поэтому ошибки мономорфизации видны. Рантайм-проверки `require_overloaded_add`, `destructure_owner`, `indirect_deref` перенесены в ui (они теперь не компилируются); `IndirectSteps` получил `KernelType`, и чтение поля цели `Deref` по-прежнему отклоняется без вызова `deref` (поля нет в layout).
- Снимки ui сгенерированы на 1.94.1 (stable печатает укороченные пути трейтов).
- Документация: `docs/splice-language.md` (абзац о том, что специализация не запускает пользовательский код), `docs/splice-api-cases.md`.
- Проверки: `cargo +1.94.1 xtask ci --quick` зелёный.

### Ф7.5 — `print` по запросу (MAC-10 частично)

### Ф7 — решение владельца: Rust-ядер нет (коммит 53cb829)
- Решение владельца («удаляй тогда»): ядро всегда понижается в IR. Удалены `#[kernel(rust)]`, Rust-регион как запасной путь для непонижаемого тела (`splice-macros/src/import*`, `splice-core/src/imports.rs`), владеющие захваты аргументов `build`, путь «owned scope» для агрегатов с деструктором (`scalar/lower/owned.rs`, `has_destructor`), трейт `StaticRustCall`/`StaticRustSymbol::of`. Такой код теперь — ошибка компиляции (агрегат с drop glue — пост-мономорфизационная, ui `comptime_drops.rs`), а если известно только при сборке — `BuildError`.
- Что оставлено: вызов обычных Rust-функций и методов из ядра (Rust-call ABI, `StaticRustSymbol::new`, `__splice_choose_rust` для обычных трейтов), операции Rust-контекста над `&mut T`. Критерий: Rust-код исполняется только как явный вызов по пути из понижаемого тела; само тело ядра никогда не «уходит в Rust».
- Выбор дизайна для методов: метод в `#[kernel] impl`/`trait`, который не понижается, — ошибка компиляции («keep a Rust method in an ordinary impl/trait»), а не тихо оставленный Rust-метод: одно правило для всего блока, без второй разметки. Rust-методы того же типа пишут во втором, обычном `impl`. `#[kernel(...)]` на методе — ошибка «put #[kernel] only on the enclosing impl or trait».
- Обесценены (закрыты без реализации): MAC-01 (откат — больше нечему откатываться), MAC-19 Rust-сторона (`PublicApi` теперь только у IR-пути), проверки регионов и `region::Collect` (MAC-06 часть), владеющий scope для агрегатов с деструктором, непрозрачные Rust-результаты (`Option<&u8>`, `impl Iterator`), `__SPLICE_REGION_*`, SPL-04 (а: молчаливого отката нет по построению).
- Тесты: `rust_regions.rs` → `staged_calls.rs` (Rust-ядра удалены; `matched_stages` и `wide_result` — теперь понижаемые ядра, `PublishedWideRule::widen` без `Self::Output`); из `language.rs` удалены тесты Rust-ядер (`first_byte`, `captured_value`, `total`, `constant`, `borrowed_iter`, `overloaded_add`, `runtime_counter`, `use_callback`), проверка `short_borrow_for_effect` сохранена и усилена (`counter` не тронут); `hygiene.rs` — ядро с пользовательским `CallArgs` понижается; ui `.stderr` перегенерированы, ui-pass `guarded` удалён (агрегат с деструктором теперь ошибка). ### Ф7.1d — `PrepareHost` как эмиттер токенов (MAC-20, коммит 82c0b78)
- `scalar/lower/host.rs`: `PrepareHost` больше не клонирует выражение и не понижает части клона. Он обходит узлы тела и передаёт понижению (`required`, `plan_iterable`, `body.comptime`) только их; печатается копия узла, в которую подставлены переписанные дочерние узлы (`Children`/`Replace` в одном порядке обхода; дочерний узел разбирается обратно, чтобы принтер syn расставил скобки приоритета — `(*поле)[i]` в `schema_plan`).
- `vec!`: элементы разбираются один раз в `kast` (как аргументы `comptime!`), имена внутри связаны с объявлениями; `HostCheck` и `PrepareHost` их не перепарсивают. Юнит `kast::tests::vec_elements_are_parsed_once_and_resolved`.
- Найдено, отложено: `comptime!` внутри `vec!` в host-выражении вне host-цикла остаётся макросом («cannot find macro `comptime`»), как и до шага (не регрессия; с первой версией эмиттера это была паника — исправлено разбором `vec!` в `kast`). `required_expr` (comptime.rs) по-прежнему перепарсивает `comptime!` и держит свои `HashSet<String>` областей — это MAC-06/MAC-18.
- Проверки: `cargo +1.94.1 xtask ci --quick` зелёный; полный `cargo +1.94.1 xtask ci` зелёный на 53cb829.

### Ф7.1e — ошибки предыдущего шага, MAC-23, MAC-12 (коммиты d364b8e, a2c59cd, 2f3af84)
- d364b8e (ошибка а): `let w = W(c); w.0` — локал, инициализированный вызовом, у результата которого тело читает поле (`kast::Body::projected_local`), — агрегат, как литерал структуры; свидетель конструктора проверяет образцом `let W(_, ..) = …`, что вызываемое — кортежная структура (вызов функции там — ошибка компиляции, ui `bodies.rs::projected_call`). Вычислитель строит такой агрегат как Rust. Тест `language.rs::tuple_struct_constructors_take_runtime_fields` (не компилировался: «runtime value used in a comptime expression»).
- d364b8e (ошибка б): `comptime!` в host-выражении вне host-цикла (элементы `vec!`) вычисляет генератор: `HostCheck`/`PrepareHost` больше не различают «внутри host-цикла» (флаг `guarded_loop` удалён), нативное тело переписывает `comptime!` и внутри токенов `vec!` (`kast::vec_elements` — один разбор для `resolve` и нативного тела). Тест `comptime_in_host_vec_elements_is_evaluated` (`vec![comptime!(n)]`, `vec![comptime!(n + 1), 2]`, `vec![comptime!(n * 2); 2]`; не компилировались).
- a2c59cd (MAC-23): `#[cfg]`/`#[cfg_attr]` на параметрах функции или метода — развёртка по каждому сочетанию условий (`declaration::configured_parameters`): копия элемента с `#[cfg(all(..))]` и применёнными условиями, поэтому все сгенерированные списки параметров совпадают с тем, что оставит rustc. Не больше 4 условий (ui `declarations.rs::many_conditions`). Тест `configured_parameters_follow_their_conditions` (функция и метод `#[kernel] impl`). Документация: `splice-language.md`.
- 2f3af84 (MAC-12 остаток): `break value` из runtime-`loop` — регистр значения в кадре цикла (тип задаёт первый `break`), также `break 'label value` из вложенного цикла; host-`loop` имеет стадию Host своего значения. Known-`match` с runtime-guard — цепочка «образец выбран генератором → guard в IR → следующая подходящая ветвь» до первой ветви, выбранной наверняка; `print` печатает её как `if/else if`. Тесты `break_values_leave_runtime_loops`, `known_match_runtime_guards_fall_through` (4 бэкенда, build и compile(ir), print); ui `unsupported_kernels.rs` закреплял старое ограничение (`break n`) — кейс удалён.
- Проверки: fmt, clippy `-D warnings` (splice-macros, splice-kernel, splice-core), `cargo test -p splice-kernel -p splice-macros --release` зелёные.

### Ф7.1f — привязки по объявлению, один вычислитель (MAC-18, MAC-06 частично; коммиты 3668f67, 6439534)
- 3668f67 (MAC-18): `Lower.bindings` — `HashMap<DeclId, Binding>`, путь разрешается через `kast` (`Body::decl_of`), идентификатор образца — `Body::binding`; `kast` записывает каждый путь тела (элемент → `None`), поэтому запрос пути вне тела (клон) — внутренняя ошибка, а не тихий host. У вычислителя нет своих областей имён (`HashSet<String>` удалены), аргументы `comptime!` берутся из тела. Клоны, которые анализировала нижняя ступень, убраны (литералы структур, методы, операнды Rust-контекста, замена объекта контекста). Тест `closure_and_block_locals_shadow_runtime_parameters` (параметр замыкания с именем runtime-параметра давал «value unavailable at specialization»).
- 6439534 (MAC-06, вычислитель): удалены предпроверки `evaluable`/`pure_wide_body`/`pure_expr`/`can_fold`; единственный обход — `required_expr`. Решение: в вычислителе ядра с параметрами (входы `Option`, Rust-выражение неподдержанного узла не типизируется) такой узел делает всё тело невычислимым (`Evaluation::unevaluable`), вычислитель возвращает ошибку стейджинга — так поведение совпадает со старой предпроверкой, но решение принимает один обход. Свёртка вызова с известными аргументами — вердикт вычислителя плюс проверка сигнатуры `i32/bool` (`foldable_signature`). Тест `the_evaluator_reads_known_slices` (индекс в известный срез: старая предпроверка не знала `Index`).
- Проверки: fmt, clippy `-D warnings`, `cargo test -p splice-kernel -p splice-macros --release` зелёные; CI на 6439534 зелёный.
