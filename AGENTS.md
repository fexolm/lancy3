# Работа со Splice и Lancy

## Что считать завершённым изменением

- Перед правкой найди публичную точку входа, её потребителей и ближайший тест. Определи наблюдаемый результат и случай, на котором неполное решение даст неверный ответ. Проведи изменение через весь затронутый путь до вызывающего кода.
- Исправляй причину в слое, который отвечает за поведение. При замене механизма переведи его потребителей, тесты, примеры и документацию в рамках той же задачи. Найди ссылки на старый путь и удали ставшую ненужной реализацию. Слой совместимости оправдан только конкретным поддерживаемым контрактом.
- Выбирай простую реализацию, которую можно проверить по коду. Обрабатывай ошибки по контракту вызывающей стороны. Заглушка, фиктивный успешный результат, особая ветка под тест или TODO для обязательной части задачи означают, что работа ещё продолжается.

## Инварианты компилятора

- При изменении семантики ядра проверь оба применимых способа сборки — прямой `build::<B>` и компиляцию переносимого IR. Сверь результат Lancy и LLVM с независимым ожидаемым значением или исходной Rust-функцией. Для операций со срезами учитывай изменения буфера, в том числе записи до ошибки. При изменении текстового представления проверь листинг.
- При правке `unsafe`, FFI или JIT укажи рядом с опасной операцией, кто обеспечивает её предусловия. Для затронутого кода проверь время жизни исполняемой памяти, допустимость указателей и соглашение о вызовах Windows x64 и Linux x86-64. Различай фактический запуск на платформе и проверку по исходникам.

## Как подтвердить результат

- Для исправления ошибки используй тест, который различает старое и исправленное поведение. По возможности воспроизведи сбой до исправления и запусти тот же случай после. Для новой возможности покрой публичный сценарий и существенный граничный случай, если существующие тесты их пропускают.
- Начинай с тестов затронутого крейта. Например, `cargo test -p lancy --release` исполняет тесты самого JIT. Для изменений Rust проверь форматирование через `cargo fmt --all -- --check` и запусти Clippy для затронутых целей. Для изменений между крейтами или в общей семантике запусти `cargo clippy --workspace --all-targets -- -D warnings` и `cargo test --workspace --release`. Зависимости LLVM и C++ описаны в корневом README.
- Заявление об ускорении подкрепи сравнением до и после на одинаковой нагрузке в release с проверкой результата. Для раздельного измерения сборки и вызова ядра используй `cargo bench -p splice --bench backends`.
- Перед сдачей перечитай собственные изменения как ревьюер. Исправь найденные дефекты и повтори затронутые проверки. Сохраняй чужие незавершённые правки. В ответе приведи фактически выполненные проверки и их результат. Если что-то проверить помешало окружение, выполни доступные проверки и точно укажи оставшийся пробел.
