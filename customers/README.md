# Нагрузки для Lancy JIT

Текущий стенд сравнивает пять ядер Splice со специализированными реализациями на C++. Каждый сценарий строит функцию через `kernel_name::build::<Lancy>(...)` и исполняет её через `splice::Executable::call`. Замеры сборки включают путь от параметров специализации до машинного кода. Проход по срезам и обработка одиночного события используют один x64-бэкенд Lancy.

## Выводы исторического сравнения на 9674ad6

Выводы заказчиков и все приведённые ниже времена исполнения и компиляции относятся к версии с отдельным SSE2-бэкендом для проекций. В текущем Lancy единому HIR соответствует скалярный x64-код, а свежие числа для него печатает стенд. [Измеренная версия 9674ad6](https://github.com/fexolm/lancy3/tree/9674ad6)

**Первым продуктовым сценарием я бы выбрал меняющиеся правила для одиночных событий.** Политика устанавливается из дерева во время работы процесса, а на горячем пути исполняется специализированная функция. В основном прогоне отношение времени Lancy к C++ составило 0,98× на смешанном потоке и 1,12× на потоке с частым обычным маршрутом. Целевой допуск заказчика — 1,10× на обоих распределениях. Перед внедрением остаётся проверить публикацию новых правил при одновременных запросах.

**Следующее расширение IR — работа с памятью.** Декодеру нужны загрузки из байтового среза с учётом размера записи, SQL-проекции — чтение бита валидности по индексу. На этих двух сценариях можно измерить эффект, убрав отдельный проход подготовки колонок. Аудиодвижку дополнительно нужны узкие насыщающие операции и состояние между кадрами. Его стоит повторно оценить, когда ядро сможет принять весь блок.

| Сценарий | Чего ждёт заказчик от перехода | Результат проверки |
| --- | --- | --- |
| [Сервис маршрутизации](rules/FEEDBACK.md) | До 10% накладных расходов на одиночном событии при разных распределениях, публикация новой политики | Стоимость одиночного вызова близка к C++. Пакетный повтор остаётся дороже. Измерена задержка до первого события новой политики в одном потоке. |
| [Декодер телеметрии](decoder/FEEDBACK.md) | Прямой вход из wire-буфера, до 20% накладных расходов | Предварительный разбор и три временные колонки входят во время Lancy. На большой партии требуется 3,10× времени C++ в сборке SSE2. |
| [Полифонический DSP](audio/FEEDBACK.md) | До 20% накладных расходов на полный callback | SIMD по голосам работает. Цикл по кадрам остаётся в Rust, узлы вычисляются в `i32`. При 31 голосе Lancy тратит 3,53× времени C++. |
| [SQL-проекция](sql/FEEDBACK.md) | В пределах 1,2× времени C++, включая исходный bitmap NULL | На большой nullable-партии получено 2,19×. Проверена деоптимизация при смене данных внутри SIMD-группы и совпадение полного результата. |
| [Рекурсивный SQL-план](joins/FEEDBACK.md) | Целый запрос одним вызовом, вложенные соединения с обеих сторон, до 1,3× времени C++ на большой партии | Совпали все 40 544 выходные строки. Время составило 2,63× от C++ с объединённым проходом и SIMD-фильтром. |

Эти измерения относятся к изолированному запуску `rules`.

### Построение и задержка

Медиана из 31 построения в уже запущенном процессе, мкс. Каждое построение начинается с параметров плана и заканчивается созданием собственного исполняемого кода. Первая строка включает исполнение одного события.

| Построение | Основной прогон | Прогон с AVX2 для C++ |
| --- | ---: | ---: |
| Построить правила, выпустить baseline и получить первый маршрут | 18,40 | 12,10 |
| Правила, оптимизированная скалярная функция | 39,90 | 22,90 |
| Правила, из скалярной функции в SIMD | 26,90 | 26,70 |
| Декодер, из схемы в SIMD | 8,00 | 8,30 |
| Аудио, из конфигурации в SIMD | 12,80 | 12,50 |
| SQL, nullable-проекция в SIMD | 10,40 | 10,20 |
| SQL, проекция с полной валидностью в SIMD | 8,50 | 8,30 |

Для аудио 31 × 128 p95 одного callback составил 0,70 мкс у C++ и 2,40 мкс у Lancy в основном прогоне. Для 64 × 64 — 0,70 и 1,80 мкс соответственно. Для одиночного маршрутизатора стенд замеряет весь проход из 65 539 последовательных вызовов и делит время на число событий. p95 отдельного сетевого запроса и p99.9 аудиопотока под нагрузкой потребуют испытания внутри приложений.

## Запуск текущих сценариев

```sh
cargo run --release -p lancy-customers
cargo run --release -p lancy-customers --features avx2
cargo run --release -p lancy-customers -- rules
cargo run --release -p lancy-customers -- joins
```

Параметр сценария принимает `rules`, `decoder`, `audio`, `sql` или `joins`. Стенд сравнивает все выходные элементы с отдельным эталоном до и после замера. Затем проводит 31 пару серий, чередуя порядок C++ и Lancy. Отдельные 201 вызов дают p50/p95 на полный вход, включая накладные расходы таймера. Малые длительности на этой системе округляются вплоть до 0,00 мкс. [Код стенда](main.rs)
