# Заказчик — декодер телеметрии

Мне приходит байтовый буфер записей по 8 байт. Схему и коэффициент калибровки я получаю до первого вызова. На выходе нужен один `i32` для каждой записи. Длина буфера и число выходных элементов проверяются до первой записи. Неполный кадр отклоняется целиком.

| Смещение | Поле | Участие в результате |
| --- | --- | --- |
| 0 | flags, u8 | Бит 0 подтверждает измерение |
| 1 | channel, u8 | Выбрана схема для канала 7 |
| 2 | sample, i16 little-endian | Значение измерения |
| 4 | zero_point, i16 little-endian | Поправка нуля |
| 6 | sequence, u16 little-endian | Результат от номера не зависит |

Валидные измерения выбранного канала дают `(sample - zero_point) * 3`. Для остальных записей результат равен `i32::MIN`. Диапазона `i32` хватает даже для разности двух крайних значений `i16`.

**Реализация.** C++ читает невыровненные байты непосредственно из буфера, переставляет поля в регистрах и пишет результат за один проход. Есть блоки SSE2 по четыре записи, скалярный хвост и вариант AVX2 по восемь записей при сборке с соответствующей ISA.

В Lancy я выразил проверку заголовка и калибровку через `#[kernel]`. Маска канала и коэффициент входят в ядро через `#[comptime]`. Чтение little-endian и знаковое расширение выполняет Rust. Адаптер собирает три временные колонки `i32` порциями по 1024 записи и переиспользует 12 КиБ рабочих буферов. Полный замер включает этот проход и запись результата. На запись приходится 12 байт промежуточных данных, которые адаптер записывает, а JIT снова читает; эти байты могут обслуживаться кэшем.

**Решение заказчика.** Для прямого декодирования мне нужен входной байтовый срез с длиной, загрузки `u8` и невыровненного `i16le` с расширением до `i32`, адресация с шагом записи и проверяемый переход на ошибку. Критерий принятия — описать эту же схему средствами IR, проверить длину до записи, убрать временные колонки и уложиться в 120% времени специализированного C++ на типичных для сервиса размерах пакета. Порог 120% — моя гипотеза о допустимой плате за смену схемы без пересборки сервиса.

Проверки покрывают начало с невыровненного адреса, крайние значения измерений, длины вокруг границ SIMD и рабочей порции, неполный кадр и неподходящий размер выхода. Этот сценарий ограничен схемой с фиксированной длиной записи. Стоимость курсора, указателей длины и ошибок внутри переменных полей потребует отдельного измерения.
