# Lancy

Lancy компилирует SSA-функции над целыми, числами с плавающей точкой, машинными указателями `ptr` и масштабируемыми векторами для Windows x86-64, Linux x86-64 и Linux AArch64. Вход в JIT — `ScalarKernel::compile(&hir::ssa::Function)`. Компиляция синхронна и выпускает одну версию машинного кода.

## Функция с ветвлением

В примере блок `join` получает либо аргумент функции, либо ноль. В SSA значение, выбранное на переходе, передаётся через параметр блока.

```rust
use lancy::{hir::ssa::{Binary, Function, Op, Terminator}, ScalarKernel};

let mut f = Function::scalar(1);
let entry = f.entry();
let x = f.params(entry)[0];
let join = f.create_block();
let selected = f.append_param(join);
let zero = f.append(entry, Op::Const(0)).unwrap();
let positive = f.append(entry, Op::Bin(Binary::Gt, x, zero)).unwrap();

let yes = f.add_edge(join, &[x]);
let no = f.add_edge(join, &[zero]);
f.set_terminator(entry, Terminator::Branch { cond: positive, yes, no });
f.set_terminator(join, Terminator::Return(selected));

let code = ScalarKernel::compile(&f)?;
assert_eq!(code.call(&[-3])?, 0);
assert_eq!(code.call(&[7])?, 7);
# Ok::<(), Box<dyn std::error::Error>>(())
```

Ошибки компиляции (`CompileError`, `#[non_exhaustive]`) разделены по тому, кто может их исправить: `InvalidIr(IrError)` — ошибка верификации, `Unsupported(Limit)` — функция превышает предел JIT или цели (регистры, кадр, рабочая область, дальность перехода, размер кода, рекурсия), `Target(TargetError)` — профиль SIMD недоступен, `Os { operation, source }` — система отказала в установке кода и сохраняет имя вызова и исходную `std::io::Error`, `Internal(InternalError)` — дефект самого Lancy (источник описывает сбойный компонент). Типы `regalloc2` и `iced-x86` в публичный API не попадают. Вызовы готового кернела возвращают `CallError`: `Trap(Trap)` для ловушки, `Signature(SignatureError)` для несовпадения аргументов, `Target(TargetError)` для потока с недостаточной длиной вектора SVE.

## Числа и масштабируемые векторы

Векторные инструкции сгруппированы в `Op::Simd(Simd)`. Параметры блоков, переходы, копирование и вызовы работают с SSA-значениями всех типов. [Определение Op](src/hir/ssa/inst/mod.rs) · [Операции Simd](src/hir/ssa/inst/simd.rs)

Скалярные типы HIR включают `i8/u8`, `i16/u16`, `i32/u32`, `i64/u64`, `i128/u128`, `isize/usize`, `f16`, `bf16`, `f32` и `f64`. Тип `Type::Vector(Lane::F32)` задаёт вектор элементов `f32`. В HIR число элементов возвращает `Op::Simd(Simd::LaneCount(Lane::F32))`, а на стороне Rust ширину в байтах даёт `ScalarKernel::vector_bytes()`. Младшая полоса располагается по младшему адресу. Один HIR можно компилировать на машинах с разной шириной регистров.

```rust
use lancy::{hir::{Binary, Function, Lane, Op, Simd, Terminator, Type}, ScalarKernel};

let vector = Type::Vector(Lane::F32);
let mut f = Function::new(&[vector, vector], vector);
let entry = f.entry();
let [a, b] = f.params(entry).try_into().unwrap();
let sum = f.append(entry, Op::Simd(Simd::Bin(Binary::Add, a, b))).unwrap();
f.set_terminator(entry, Terminator::Return(sum));

let kernel = ScalarKernel::compile(&f)?;
let words = ScalarKernel::vector_bytes() / 8;
let pair = |x: f32| u64::from(x.to_bits()) * 0x1_0000_0001;
let arguments = [vec![pair(1.0); words], vec![pair(2.5); words]].concat();
let mut result = vec![0; words];
kernel.call_words(&arguments, &mut result)?;
assert_eq!(result, vec![pair(3.5); words]);
# Ok::<(), Box<dyn std::error::Error>>(())
```

| Семейство | Семантика |
| --- | --- |
| Целые | Арифметика с оборачиванием, насыщающее сложение и вычитание, сравнения, минимум и максимум, сдвиги, вращения и подсчёт битов. Знаковость типа определяет деление, сравнение и правый сдвиг. Деление на ноль и переполнение знакового деления возвращают ошибку. |
| FP | Арифметика, остаток, FMA с одним округлением, квадратный и кубический корни, минимум и максимум, округление, классификация IEEE, смена и копирование знака, логарифмы, экспоненты, тригонометрические и гиперболические функции. Сравнения возвращают ноль или все единицы. Для векторов FP результат сравнения имеет целые полосы той же разрядности. |
| Полосы и маски | `Splat`, `Iota`, `ExtractLane`, `InsertLane`, двухвекторный `Shuffle`, `Select`, `BitSelect`, `Compress`, `Expand`, `AnyTrue`, `AllTrue`, `Reduce`. Индекс вне диапазона при извлечении или вставке даёт `OutOfBounds`. Перестановка подставляет ноль. Редукция обходит полосы в порядке возрастания. |
| Преобразования | `Cast` преобразует числа, `Bitcast` сохраняет биты. При приведении FP к целому дробная часть отбрасывается, переполнение насыщается, NaN даёт ноль. Для преобразований вектора с изменением ширины элемента служат `Widen` и `Narrow`. |
| Память | `Simd::Load` и `Simd::Store` допускают невыровненный адрес. `Simd::MaskedLoad` и `Simd::MaskedStore` обращаются только к полосам с установленным старшим битом маски. `VectorAddress::indices` включает gather/scatter по знаковым индексам в элементах. При повторном индексе остаётся последнее активное значение. |

`call_words` принимает числовые аргументы и записывает результат в предоставленный срез `u64`. Каждый аргумент начинается с нового слова и занимает столько слов, сколько нужно для его типа. Узкие числа используют младшие биты. Для сигнатур с указателями доступен `unsafe call_words_raw`. Ошибка оставляет выходной срез результата нетронутым, а ранее выполненные записи по указателям видны вызывающему коду.

На x64 бэкенд выбирает ширину в 128, 256 или 512 бит по CPUID и состоянию регистров, которое сохраняет ОС. При AVX-512DQ умножение 64-битных полос использует `vpmullq`. На AVX2 и AVX-512F ту же операцию дают частичные 32-битные произведения. AVX-512F без BW обрабатывает байтовое сложение двумя инструкциями AVX2. На AVX10 бэкенд учитывает доступную ширину, на AVX10.2 использует упакованное преобразование `f32/f64` в целые с насыщением. [Правила выбора SIMD-форм](src/lir/x64/isel/rules/native.rs) · [Проверка возможностей CPU и ОС](../splice-target/src/lib.rs) · [Спецификация Intel AVX10.2](https://cdrdv2-public.intel.com/855340/361050-004-intel-avx10.2-spec.pdf)

Маскированный доступ к последовательным элементам на AVX-512 использует `vmovdqu8/16/32/64` с регистром маски. Для индексных обращений к 32- и 64-битным элементам доступны gather на AVX2 и AVX-512, scatter на AVX-512. JIT генерирует доступы по активным полосам, когда у процессора нет подходящей команды. Целочисленное деление также проверяет ошибки в порядке полос. Для синуса, логарифма и других библиотечных математических функций JIT вызывает конкретную скалярную функцию. [Маскированная память](src/lir/x64/inst/simd.rs) · [Генерация операций по полосам](src/lir/x64/inst/lanes.rs)

На AVX-512 и AVX10 канонические предикаты могут занимать `k2`–`k7`, в том числе при нескольких потребителях и передаче между блоками. `k1` используется для краткоживущих вычислений и тех gather/scatter, которые изменяют маску. `any` и `all` проверяют ненулевые полосы, а память и `select` используют старший бит полосы. Для `first_n`, `count` и записи компактного префикса выбор инструкций использует битовую маску при доказанных предусловиях. [Маски x64](src/lir/x64/isel/masks.rs)

Выбор инструкций x64 извлекает полосы с допустимым постоянным индексом из регистра. На SSE2, AVX2 и AVX-512 перестановка 32-битных полос с индексами `iota - const` для положительного сдвига в пределах пакета получает форму с заполнением нулями. Для 32-битных сдвигов и вращений полос с постоянным счётчиком используются непосредственные операнды. [Перестановки x64](src/lir/x64/isel/rules/packed_rearrange.rs) · [Целочисленные операции](src/lir/x64/isel/rules/packed_integer.rs)

Проверка последней полосы удаляется на пути, где доказано наличие полного пакета. С флагом `experimental-simd` проходы HIR дополнительно упрощают постоянные маски и перестановки, переиспользуют `splat` и `iota` и выносят их из циклов при наличии инвариантных операндов. Выбор инструкций x64 может объединить соседнюю одноразовую загрузку с упакованной операцией или broadcast. [Анализ границ](src/hir/transforms/passes/bounds.rs) · [Правила HIR](src/hir/transforms/passes/experimental/mod.rs) · [Правила x64](src/lir/x64/isel/rules/experimental.rs)

Распределитель использует общий класс физических регистров для XMM, YMM и ZMM. Слот вытесненного значения этого класса вмещает полный вектор выбранной ширины. На Windows распределитель может использовать XMM6–XMM15 и их широкие версии. При входе в JIT сохраняются младшие 128 бит тех из этих регистров, которые запишет ядро или его потомки. Обычный возврат и выход по ошибке восстанавливают их. Внутренние вызовы передают широкие аргументы в кадре, возвращают широкое значение через регистр 0 этого класса и учитывают регистры, изменённые вложенными вызовами.

## Путь от HIR до вызова

Указатель можно передать в блок или функцию, вернуть из вызова, прочитать из памяти и записать в память. Для `xs[i]` фронтенд Splice передаёт срез парой `(ptr, len)` и строит три инструкции.

```text
BoundsCheck(i, len)
addr = PtrOffset(ptr, i, Four)
value = Load(I32, addr)
```

`PtrOffset` расширяет знаковый индекс до ширины указателя перед умножением на шаг в байтах. `Load` указывает тип результата, а `Store` использует ширину записываемого значения. Оба допускают невыровненный адрес.

1. **HIR.** После проверки SSA компилятор встраивает вызовы от листьев графа к корню. Несколько возвратов передают результат в общий блок продолжения. При оценке размера вызова учитываются достижимые блоки шаблона. SCCP распространяет константы по исполнимым рёбрам и сворачивает типизированные операции. Анализ параметров блоков прослеживает переадресованные значения, в том числе по обратным рёбрам. Проходы циклов повторяют сокращающие преобразования с обновлением графа и доминаторов и выполняют один раунд клонирования по инвариантному условию. Передача значений памяти использует доказанные диапазоны срезов из анализа циклов. После удаления загрузок анализ параметров блоков обновляется, чтобы удаление мёртвого кода могло учесть новые значения. Этот проход начинает обход с ветвлений, возвратов и операций с эффектом или возможной ловушкой. [Инлайнер](src/hir/transforms/passes/inline.rs) · [Упрощение SSA](src/hir/transforms/passes/simplify.rs) · [Анализ границ](src/hir/transforms/passes/bounds.rs)
2. **Выбор инструкций и LIR.** Общий проход обходит SSA от потребителей к определениям. Правило x64 может покрывать несколько операций HIR и выпускать последовательность LIR с виртуальными регистрами. Например, сравнение, использованное только ветвлением, превращается в `BrCmp`. Загрузка поглощает одноразовый `PtrOffset`, а знаковое расширение переменного индекса остаётся явным. Для `i32` с постоянным делителем x64 вычисляет частное сдвигом с поправкой знака или умножением на обратный коэффициент. Остаток выводится из частного. Делители `0` и `-1` проходят через проверку ошибок. Операции памяти и проверки сохраняют порядок. После преобразований HIR модуль передаёт актуальный `CallGraph` в LIR. Трейт `TargetInst` задаёт ограничения регистров выбранной инструкции. [Обход SSA](src/lir/isel.rs) · [Правила x64](src/lir/x64/isel/rules) · [Контракт инструкции](src/lir/inst.rs)
3. **Планирование инструкций.** После выбора инструкций локальный планировщик учитывает зависимости SSA, длину критического пути и давление по классам регистров. Для регистров в участках с допустимыми перестановками планировщик по запросу определяет живость на выходе блока. Обратный обход от использований до места определения учитывает аргументы рёбер. Планировщик сохраняет взаимный порядок чтений, записей и проверок. [Планировщик](src/lir/schedule.rs) · [Анализ живости](src/lir/schedule/liveness.rs)
4. **Распределение регистров и эмиссия.** Общий проход использует Ion из `regalloc2`. Компиляция идёт от вызываемых функций к вызывающим, поэтому на месте вызова известно, какие регистры может перезаписать всё поддерево вызовов. Раскладка использует вложенность естественных циклов из HIR. Блок на критическом ребре получает глубину общей петли его концов. Переход на следующий блок становится fallthrough вместе с подготовленными для этого пути перемещениями. [Проход regalloc](src/lir/regalloc.rs) · [Раскладка блоков](src/lir/layout.rs) · [Эмиттер x64](src/lir/x64/emit.rs)
5. **JIT.** Рантайм владеет исполняемым кодом до уничтожения `ScalarKernel`. Для сигнатуры из `i32` используется `call`. При вызове `unsafe call_raw` вызывающая сторона отвечает за валидность указателей. Безопасный интерфейс Splice принимает Rust-срезы и проверяет права доступа. Записи до ошибки индекса или деления видны вызывающей стороне. [ScalarKernel](src/jit/kernel.rs)

`ScalarKernel::compile` по умолчанию использует `Inlining::Always` без порога размера тела. Если полное разворачивание общего графа превышает диапазон индексов компилятора, вызовы сохраняются. Рекурсивный граф по-прежнему возвращает `CompileError::Unsupported(Limit::Recursion)`. Для явного сохранения вызовов доступен `ScalarKernel::compile_with_inlining(&function, Inlining::Never)`.

Специализация Rust-параметров `#[comptime]` выполняется во фронтенде Splice до передачи операций в Lancy. В приложении с макросами используйте `#[splice::kernel]` и `my_kernel::build::<splice_lancy::Lancy>(...)?`. [Язык и примеры Splice](../README.md) · [Политика повторных попыток](../splice/examples/retry_policy.rs)

```sh
cargo test -p lancy --release
cargo test -p splice-lancy --release
cargo run -p splice-kernel --release --example retry_policy
```

Для проверки отдельных проходов добавьте текстовый SSA-сценарий в `lancy/filetests`. Каждый файл автоматически становится отдельным Cargo-тестом. Ожидаемые преобразования HIR, LIR, назначения регистров, машинные инструкции и примеры выполнения задаются рядом с исходным IR. [Формат и команды запуска](filetests/README.md)

Типизированные константы распространяются по достижимым рёбрам SSA. Целочисленные операции сворачиваются с учётом ширины и знаковости скаляра или одинаковых полос SIMD-вектора. Для ациклического графа достаточно обхода в топологическом порядке, а для циклов SCCP обновляет только потребителей изменившихся значений. Пустые ветви, которые передают одно различающееся числовое значение в общую точку, сворачиваются в скалярный или SIMD-`select`.

Естественные циклы распознаются по доминаторам и обратным рёбрам. Передачи между параметрами SSA учитываются при доказательстве инвариантности. Дешёвые операции со скалярами и SIMD-векторами могут перейти в предзаголовок, если операнды там доступны и операция гарантированно завершается без ошибки. Для широких и векторных вычислений выбор учитывает ветвления внутри тела и число значений, которым нужны векторные регистры.

Счётные циклы с положительным шагом, включая `LaneCount`, удаляются при доказанном завершении и отсутствии наблюдаемых эффектов. В цикле `end - i >= LaneCount` условие доказывает диапазон полного пакета и ограничивает прибавление шага. Для циклов `i < end` с шагом `+1` живые результаты простых аддитивных рекуррентностей до второй степени заменяются формулами с сохранением переполнения `i32`.

Проверки границ и ветки коротких записей убираются, когда для каждой затронутой полосы доказан допустимый диапазон. Загрузки из объявленных общих срезов переносятся в предзаголовок, если адрес инвариантен и весь диапазон чтения уже подтверждён. Соседние линейные проходы с одинаковыми итерациями могут слиться, если их скалярные или SIMD-обращения не пересекаются между итерациями. Для разных баз доказательство использует непересекающиеся объявленные срезы и проверяет диапазон обоих обращений.

Общий проход HIR переиспользует значения обычных загрузок и полных записей одного типа по точному адресу, включая указатели и SIMD-векторы. Одинаковые маскированные чтения также могут переиспользовать результат, если совпадают значения неактивных полос. Полная перезапись удаляет более раннюю запись на прямолинейном участке, если между ними отсутствуют наблюдающее чтение, вызов или возможная ошибка. [Проход](src/hir/transforms/passes/memory.rs) · [Тесты](filetests/passes/memory-forwarding.lancy)

В небольшом естественном цикле без вложенных циклов, с одним входом и общим выходом, Lancy может вынести одно ветвление перед циклом. Условие должно быть уже доступно в предзаголовке. Каждая копия цикла выполняет свою ветвь и передаёт результат в общий выход.

## Бэкенд AArch64

На Linux AArch64 `ScalarKernel::compile` проходит через общий обход SSA, правила выбора AArch64, LIR с виртуальными регистрами и Ion из `regalloc2`. Эмиттер использует выбранные физические регистры и вставленные Ion перемещения для рёбер и вытеснений. Точка входа и библиотечные вызовы следуют AAPCS64. Внутренние вызовы передают аргументы в рабочей области и возвращают целое в X0, FP или вектор в V0/Z0. При входе JIT сохраняет регистры AAPCS64, которые могут перезаписать ядро и его потомки, и восстанавливает их на обычном возврате и при trap. [Правила AArch64](src/lir/aarch64/backend/isel/rules) · [Распределение регистров и кадр](src/lir/aarch64/backend/compile.rs) · [Эмиссия](src/lir/aarch64/backend.rs)

`SPLICE_SIMD=neon|sve|sve2` выбирает формы арифметики, преобразований, сравнений и редукций. Целочисленные `Div` и `Rem` сообщают ошибку по первой сбойной полосе. SVE делит 32- и 64-битные полосы предикатными инструкциями и расширяет узкие полосы группами. NEON делит по полосам встроенными `SDIV` и `UDIV`. Для 128-битных чисел AArch64 использует пары регистров и деление с восстановлением остатка. SVE выполняет упорядоченную редукцию суммы `f32` и `f64` через `FADDA`.

SVE учитывает логическую ширину при маскированных обращениях, gather/scatter, перестановках и преобразованиях ширины. Узкие индексные обращения выполняются группами расширенных полос, а 128-битные полосы используют пары 64-битных обращений. NEON обращается к памяти активных полос через скалярные инструкции. Scatter выполняется в порядке полос, поэтому при совпадении адресов побеждает последняя активная полоса.

`Compress` на SVE использует `COMPACT`, на NEON — векторные перестановки. Оба пути сохраняют порядок активных полос и заполняют остаток нулями. `Expand` на SVE использует префиксный подсчёт и `TBL`. На SVE2 префикс для 32- и 64-битных полос вычисляет `HISTCNT`. Для 128-битных полос `Expand` и `Shuffle` работают с парами соседних 64-битных элементов. SVE2 выполняет побитовый выбор через `BSL` и сводит пару XOR к `EOR3` при одноразовом промежуточном результате в том же блоке. Перед вызовом SVE-ядра `CNTB` проверяет текущую длину вектора потока.

Основные операции F16 и BF16 генерируются через расширение до `f64` и округление в исходный формат. BF16 FMA учитывает невместившуюся в `f64` часть суммы на точной середине округления. FP-остаток вычисляется точно по целым значащим частям, включая субнормальные значения. Преобразования из 128-битных целых в FP округляют один раз в целевой формат. Редукции FP выполняются по порядку полос с округлением после каждого шага. Общие числовые примитивы пока используются для оставшихся форм, включая трансцендентные функции.

## Энкодер AArch64

Энкодер находится в `lancy/src/lir/aarch64` и доступен через `lancy::aarch64`.

`Encoder` принимает адрес начала целевого блока и буфер вызывающей стороны. Передайте точную форму `Code` и типизированные операнды или используйте `push_instruction` для готовой инструкции. Для PC-relative перехода `Operand::label` принимает абсолютный целевой адрес. После размещения блоков `patch` может закодировать инструкцию заново по тому же PC. Результат доступен через `bytes()` в little-endian представлении. Выбор ISA, размещение блоков и установка кода принадлежат вызывающей стороне.

Энкодер содержит формы скалярной арифметики, обращений к памяти и переходов, векторные операции NEON и SVE, предикатные загрузки и записи SVE, а также `EOR3`, `BSL`, `HISTCNT` и непредикатный `MUL` из SVE2. Точные формы перечислены в `Code`. Тесты сверяют машинные слова с LLVM. [Пример API](src/lir/aarch64/mod.rs) · [Формы инструкций](src/lir/aarch64/instruction.rs)
