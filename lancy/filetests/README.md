# Тесты проходов Lancy

Добавьте файл с расширением `.lancy` в этот каталог или любую его подпапку. Cargo автоматически зарегистрирует файл как отдельный тест. Например, для [passes/inline-fold.lancy](passes/inline-fold.lancy) имя заканчивается на `ir_passes_inline_fold`.

```sh
cargo test -p lancy --release --lib ir_ -- --list
cargo test -p lancy --release --lib filetests::ir_
cargo test -p lancy --release --lib ir_passes_inline_fold
```

## Первый тест

```text
fn main x:i32 -> i32
  a = const 3
  b = const 4
  seven = add a b
  result = add x seven
  ret result

@source check: Add
@opt check: const 7
@isel check: alu.Add imm=7
@run -7 -> 0
@run 2147483647 -> -2147483642
```

Каждая директива проверяет свой проход. При несовпадении Cargo показывает файл, этап, строку начала проверок и фактический листинг с отметками FileCheck. Чтобы посмотреть листинги успешного теста, установите `LANCY_FILETEST_DUMP=1` и передайте `-- --nocapture`.

| Этап | Что доступно для проверки |
| --- | --- |
| `@reject` | Подстрока ожидаемой ошибки верификатора. Задаётся отдельным сценарием. |
| `@source` | Верифицированный SSA, операнды, параметры блоков, граф вызовов. |
| `@cfg` | Блоки в обратном постпорядке, предшественники, преемники и доминаторы. |
| `@inline` | SSA после инлайнинга. Директива `@policy never` сохраняет вызовы, по умолчанию используется `always`. |
| `@opt` | SSA после свёртки констант, распространения копий, удаления недостижимых блоков, мёртвых вычислений и дублирующих проверок границ. |
| `@isel` | Выбранные x64 LIR-инструкции, ограничения виртуальных регистров, блоки и аргументы рёбер. |
| `@alloc` | Физические операнды, spill-слоты и перемещения в порядке эмиссии. Распределение дополнительно проверяет checker из regalloc2. |
| `@asm` | Смещения, байты и Intel-дизассемблирование сгенерированного кода, включая обёртку ABI текущего хоста. |
| `@run` | Результат либо конкретная ошибка на заданных аргументах. Один вектор проверяется интерпретатором на исходном, встроенном и упрощённом SSA, затем через публичный JIT. |

Этапы листинга принимают директивы FileCheck. `check:` ищет фрагменты по порядку, `nextln:` требует следующую строку, `sameln:` проверяет ту же строку, `not:` запрещает фрагмент в интервале между проверками. Для номеров регистров и слотов доступны именованные регулярные выражения. [Синтаксис FileCheck](https://docs.rs/filecheck/0.5.0/filecheck/) · [Пример со spill-слотами](cranelift/spill-reload.lancy)

На AArch64 общие сценарии проверяют `@run` и `@reject`. В `aarch64/` директивы `@aarch64-isel` и `@aarch64-alloc` используют FileCheck для LIR с виртуальными регистрами и листинга после распределения регистров. Директива `@aarch64` сопоставляет машинные слова с маской и значением. Например, `@aarch64 sve2 has 0xff20fc00 0x04206000` требует непредикатный SVE2 `MUL`. Доступны условия `has` и `lacks` и профили `all`, `neon`, `sve`, `sve2`. [Выбор инструкций](aarch64/isel.lancy) · [Кодировки SIMD](aarch64/packed.lancy) · [Перестановки](aarch64/rearrange.lancy) · [Редукции](aarch64/reduce.lancy) · [Встраивание вызовов](aarch64/inlining.lancy)

## Формат IR

У каждого независимого сценария есть точка входа `fn main`. Вспомогательные функции объявляются выше вызывающей функции. Параметры записываются как `имя:тип`. Например, `x:i32`, `p:ptr`, `scale:f64` или `xs:vec.f32`. Строка `block имя параметры` объявляет блок. Имена значений уникальны в пределах функции. Целые литералы записываются десятичным числом или 32-битным шестнадцатеричным словом с префиксом `0x`. Строка `---` разделяет сценарии одного файла, а `#` в начале строки обозначает комментарий.

| Запись | Операции |
| --- | --- |
| `v = op a b` | `add sub mul div rem and or xor eq ne lt le gt ge shl shr min max` |
| `v = simd.lanes f32`, `v = simd.splat x`, `v = simd.iota i32` | Число полос, заполнение скаляром, последовательные номера полос |
| `v = literal f32 3f800000`, `v = cast f32 x`, `v = bitcast i32 x` | Литерал по шестнадцатеричному битовому представлению, числовое преобразование, переинтерпретация битов |
| `v = sqrt x`, `v = fma x y z`, `v = simd.reduce add xs` | Поэлементная операция, FMA, свёртка в скаляр |
| `v = simd.maskedload p indices mask fallback`, `simd.maskedstore p - mask v` | Доступ по индексам в элементах или к последовательным полосам при `-` |
| `v = const 7`, `v = copy x`, `v = call helper x y` | Константа, копия, прямой вызов |
| `bounds i len`, `p = offset base i 4` | Беззнаковая проверка границ и адресация с шагом 1, 2, 4 или 8 байт |
| `v = load i32 p`, `store p v` | Тип загрузки указывается явно, ширина записи определяется типом значения |
| `ret v`, `jump join a b`, `br cond left a \| right b` | Возврат и передача аргументов по рёбрам |

Для `@run` допустимы ошибки `!zero`, `!overflow` и `!bounds`. У функции вида `(ptr, i32...) -> i32` можно задать входной и ожидаемый выходной буфер: `@run 7 -> 7 | aa aa aa aa | 07 00 00 00`. Числа перед стрелкой передаются после указателя. Интерпретатор проверяет каждый исполненный доступ к буферу до запуска машинного кода. Такой сценарий поддерживает невыровненные числовые чтения и записи, включая активные полосы векторных операций и сверяет все байты, в том числе при ошибке. [Пример с записью до ошибки](passes/store-before-trap.lancy)
